# SociyoHub Android release

SociyoHub is an Android Trusted Web Activity (TWA) for `https://sociohub.live`. The canonical input is `android/twa-manifest.json`; generate the Gradle project into the ignored `android/.build/` directory. Do not run `bubblewrap init` or hand-edit generated Gradle files.

## Fixed release identity

| Setting | Value |
| --- | --- |
| Application ID | `live.sociohub.app` |
| App/version | `SociyoHub` / `1.0.0` (`versionCode` 1) |
| Origin/start URL | `https://sociohub.live/?source=twa` |
| Generator | `@bubblewrap/cli@1.25.0` |
| Android target | API 36 (generated by pinned Bubblewrap) |
| Minimum Android | API 23 |
| Orientation/fallback | Portrait / Custom Tabs (never WebView) |

The TWA has no JavaScript bridge or local-file bridge. Browser/TWA navigation, back, keyboard, camera capture, and file chooser behaviour remain browser-owned. Only `sociohub.live` is trusted; links outside that verified origin open in browser UI. Authentication remains the existing web flow (email/password, Firebase Phone OTP, Google, session exchange, expiry and logout). Server RLS remains authoritative. Razorpay is only for SociyoHub SaaS subscriptions; society maintenance remains Cash or Bank Transfer.

Bubblewrap's generated manifest may include only the permissions required by Android Browser Helper features (not blanket camera or storage access). Inspect the generated manifest and final AAB before upload; reject unexpected dangerous permissions. Camera capture and uploads currently use browser file inputs, so permission denial remains a browser flow and no native QR bridge is enabled.

## Prerequisites

- A trusted owner machine with 64-bit JDK 17 and `JAVA_HOME` configured.
- Android SDK command-line/build tools for API 36 with `ANDROID_HOME` configured. Bubblewrap may install missing SDK components interactively.
- Bun (for repository verification) and npm/npx.
- The owner's upload keystore, stored outside this repository.
- `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD` supplied by a local secret manager or a non-recorded shell session. Never place passwords in a command, file, shell history, log, or documentation.

No private key, keystore, password, debug signing, Play credential, or Razorpay server secret belongs in source control. Keystore/JKS and Android build outputs are ignored. The release command below refuses a missing keystore and does not create one.

## One release-build path

From the repository root:

```bash
bun run verify:android
export BUBBLEWRAP_KEYSTORE_PASSWORD       # enter through your secure local mechanism
export BUBBLEWRAP_KEY_PASSWORD            # enter through your secure local mechanism
bash android/release.sh /absolute/path/to/upload-keystore.jks
```

The script pins Bubblewrap 1.25.0, regenerates the project from the committed manifest, requires external signing passwords, and builds the signed bundle. Expected output:

```text
android/.build/app-release-bundle.aab
```

This environment has no JDK or Android SDK, so repository checks can pass here but no signed AAB is claimed.

## Verify the AAB before upload

```bash
# Confirm the archive is readable.
unzip -t android/.build/app-release-bundle.aab

# Install Google bundletool locally, then inspect the signed bundle.
java -jar /path/to/bundletool.jar validate --bundle=android/.build/app-release-bundle.aab
java -jar /path/to/bundletool.jar dump manifest \
  --bundle=android/.build/app-release-bundle.aab \
  --xpath=/manifest/@package
```

The package output must be `live.sociohub.app`. In Play Console, confirm version code 1, production origin, target API, permissions, and the signer before release. Do not upload an APK; upload the AAB.

## Version increments

For every future upload, edit both `appVersionCode` and `appVersionName` in `android/twa-manifest.json`. `appVersionCode` must strictly increase. Re-run `bun run verify:android` and the release script. Never change `packageId` after the first Play upload.

## App Links / Digital Asset Links

The server route `/.well-known/assetlinks.json` is fail-closed. It always uses `live.sociohub.app` and returns `[]` until this server-only deployment value is set:

```text
ANDROID_SHA256_CERT_FINGERPRINTS=<Play App Signing SHA-256 fingerprint>
```

Use the **Play App Signing app certificate** fingerprint, not an invented value and not merely the upload certificate. Multiple real fingerprints may be comma-separated during rotation. After deployment, verify an unauthenticated `200` JSON response at `https://sociohub.live/.well-known/assetlinks.json`. Until then, browser chrome is expected and the origin is not claimed as verified.

## Play Console owner-only handoff

1. Use the owner's Google Play developer account, enable Play App Signing, retain the upload keystore and credentials outside source control, and build/verify/upload the signed AAB. Inspect the final merged manifest and AAB permissions before upload.
2. Copy the Play App Signing SHA-256 fingerprint to the server variable above, deploy, then check App Links in Play Console and on a test device.
3. Enter privacy policy `https://sociohub.live/privacy` and account deletion `https://sociohub.live/gdpr`.
4. Complete Data Safety and content rating from actual production behaviour; do not copy assumed answers. Review authentication identifiers, profile/contact/KYC data, society/flat records, uploads, visitor/security records, payment records, diagnostics, web push, Firebase, Supabase, Razorpay, and deletion/retention behaviour.
5. Provide screenshots captured from the signed app, store listing, support contact, release notes, target audience, countries, pricing, app access/reviewer credentials, and internal/closed testing evidence. Do not fabricate claims or assets.
6. Verify email/password, Phone OTP, Google sign-in/session exchange, logout, expiry, account switching, deletion request, uploads/camera capture, notifications/deep links, external links/back navigation, and Cash/Bank Transfer maintenance on real devices before production rollout. Preserve the documented email/password provider limitation.

One external dependency remains: **Generate and sign the AAB on a machine with the required Android tooling, then upload it to Google Play Console.**
