# Domain architecture rules (backend, finance, gate, governance)

- Security service integration uses deterministic synthetic Society A/B adapters; Flat 360 role decisions use authenticated self-check RPCs, while only canonical eligibility uses the trusted server client.
- Razorpay SaaS payments use one server-only provider module, atomic request/event/refund records, and canonical database finalizers; maintenance remains Cash and Bank Transfer only to prevent duplicate payment domains.
- Android releases use the pinned Bubblewrap manifest and release script; generated Gradle output and signing material stay outside source control.
- Public ingress uses strict bounded schemas, redacted failures, and the shared atomic HMAC-fingerprinted limiter; this prevents amplification and race-prone local throttles.
- Vulnerable transitive runtime packages are pinned via package.json overrides to in-major patched releases; this fixes advisories without forcing breaking upgrades.
- Scheduler hooks accept CRON_SECRET or the DB-held pg_cron token (verify_scheduler_token); automation config writes go only through admin_set_society_automation, which enforces permission, Premium and audit.
- Society Custom Branding lives in society_branding (strict hex/name/logo-path CHECKs) written only via admin_set/reset_society_branding RPCs (admin + Premium + audit); logos are re-encoded PNGs in the private branding bucket; this keeps branding separate from bill-template logo_url/bill_theme.
- Bank-statement reconciliation stores imported rows in bank_statement_imports/lines as evidence only; the only path to "matched" is the human confirm_bank_line_match RPC, serialised per society by an advisory lock, with a unique index so one record links to one bank line. Never alter payments/receipts/ledger from a bank match.
- SaaS subscription price = active flats × plans.price_per_flat_inr, computed only by saas_subscription_quote; claim_saas_subscription_order recomputes and rejects mismatches or societies above pricing_settings.enterprise_threshold_units (custom pricing). Plan ids stay basic/pro/premium (shown as Starter/Growth/Pro) so existing entitlements keep working.
- Gate arrivals (guest, delivery, service, cab) share one visitors state machine; public.gate_transition_allowed + trigger trg_enforce_gate_transition make transitions authoritative for every write path, so no per-type state machines.
- Notifications go through public._notify_user / public._notify_flat (service/definer only, society-tagged) into user_notifications; FCM tokens are delivery only — never a second notification store.
- AI features read society sources only via src/lib/ai-retrieval.server.ts (server-resolved society + caller's RLS client); never a client-supplied scope or the admin client.
- Canonical financial truth stays bills → payments/receipts → ledger, with income/expenses/reconciliation/No-Dues/reports reading those tables; new features consume them, never a parallel model. Flat 360 (flat360.functions.ts) is the flat-level admin support surface to extend.
- Services & Discovery reuses public.ads (kind banner/service/campaign) + service_categories; residents read only via list_discovery_items (server-resolved society/city/plan, dates, Pro ad-free) through listDiscovery, which signs private images server-side; DB CHECKs block unsafe text/URLs/phones and interstitial placement, triggers audit + rate-limit every change.
- Auditor Pack reads only via get_auditor_pack (reuses get_finance_overview + get_receivables_ageing, _finance_require_admin, rate limit, audit row); files are built on the device and never stored, so no second financial truth or public export storage.
- Surveys extend polls (polls.kind = survey) with survey_questions/survey_responses; writes only via admin_create_survey / admin_set_survey_status / submit_survey_response and results only via get_survey_results, so there is one communication system with server-validated answers.
- Full society export reads only via get_society_export_section (society.settings permission, per-section column whitelist, 1,000-row pages, rate limit, audit row); files are built on the device and never stored, so exports can't leak secrets or cross societies.
- Public schema.org JSON-LD comes only from src/lib/structured-data.ts (one @graph with stable @ids, facts from BRAND) so pages never emit conflicting entities.
- React Query mutations use networkMode "always" with retry off, so writes fail visibly offline and are never auto-replayed on reconnect.
- Tenancy lifecycle state is derived by public.tenancy_state from flat_residents dates/flags (never stored or client-set); transitions go only through admin_renew_tenancy / admin_move_out_resident (No-Dues gated via compute_no_dues_eligibility_internal, reasoned override) / admin_archive_tenancy, and renewal reminders dedupe via tenancy_reminders_sent on the existing daily expiry cron.
- flat_residents keeps one row per occupancy (history is never overwritten); a partial unique index allows only one active row per person+flat, and end_resident_unit_relationship is an admin-correction-only path (reason, residents.manage, dues-blocked, audited) — normal leaving always uses admin_move_out_resident.
- Workstream 3 gate/safety extends the single visitors state machine: recurring passes, restricted list, incidents, SOS and visitor parking (visitors.parking_slot_id, one active use per slot) are separate small tables written only via SECURITY DEFINER RPCs with server-resolved society, audit and rate limits; offline guard mode may queue only walk-in (with house) and checkout, replayed via guard_offline_replay with one-time op ids and conflict results — never approvals, overrides, parking, SOS or permissions.
- Workstream 4 operations extend canonical systems: helpdesk (support_tickets + on_hold/reopened, server-set SLA, escalation, staff/vendor/asset links, ratings, private evidence via helpdesk-evidence server fns), finance_vendors (contract/AMC columns), and new society_staff/staff_attendance/society_assets/asset_service_log/inventory_items/inventory_movements written only via audited, rate-limited SECURITY DEFINER RPCs; expenses are referenced, never duplicated, and inventory holds quantities only.
- Procurement (procurement_requests/quotations/events) and budgets (society_budgets + append-only revisions) are reference-only layers written via proc_*/budget_set RPCs with finance-admin auth, separation of duties and a transition trigger; budget actuals come only from posted expenses and a request completes only by linking a posted expense, so there is no second money record.
- Procurement evidence files live in procurement_attachments + private procurement-evidence bucket, written only via uploadProcurementEvidence (byte-sniffed, 5 MB) → proc_record_attachment; removal is a reasoned soft-remove while the stage is open, so historical evidence is never deleted and never touches expenses/ledger.
- Workstream 6 governance extends canonical systems: notices gain priority/expiry/ack (notice_set_controls, notice_acks, hourly idempotent publish_due_notices; "delivered" is never claimed), formal votes are polls.kind='vote' written only via vote_* RPCs with freeze/immutability triggers and choice-free audit, the document vault is society_knowledge_sources + append-only society_document_versions (replace archives, documents never deleted), and meetings/privacy_requests are small SECURITY DEFINER-written tables; privacy deletion never removes financial, security or audit records.
- Workstream 7 bill adjustments live in append-only bill_adjustments written only via admin_add_bill_adjustment (billing.manage, strict money, idempotent request id, never below zero outstanding, counter-entry corrections); they change dues/ageing only, never the bill row or the cash-basis journal. Handover status lives on society_settings via admin_set_handover_status (audited), with no builder role.
- Workstream 7 bill runs: when bill_run_approval_required is on, bills may only be created by finalize_bill_batch with a different admin's approval whose fingerprint still matches (trigger trg_bills_require_approved_run blocks unbatched run inserts; one-off/single-flat bill functions opt out); late fees are opt-in, server-computed, once per run.
- Opening balances are evidence rows: unverified/rejected never count; confirmed ones count in get_receivables_ageing and No-Dues until carried once into the next bill run's previous_balance (carried_bill_id), so there is no second dues system.
- Workstream 8: cross-domain search only via global_search and Needs Attention only via get_needs_attention (SECURITY INVOKER, society from profile, role gates + RLS, deterministic, no counters); scheduler hooks wrap their body in recordSchedulerRun (scheduler_job_runs: one claim per job+window, stale >30 min retried); deduped notifications go through _notify_user_once (user_id+dedupe_key unique).

- AI record summaries (helpdesk request, meeting, needs-attention) go only through summarizeRecord → ai-retrieval.server.ts readers (caller RLS client, server-resolved society) and the shared ai-responses.server.ts caller; read-only, labelled AI-generated.
- In-database cron jobs run only via run_logged_db_job (whitelisted job names) so every run is logged in scheduler_job_runs with skip/retry/recovery counts; scheduled reminders send only via _notify_*_once with stable event dedupe keys; users may change only read_at on user_notifications (trigger), so priority stays server-set.
- Heavy export libraries (jspdf, jspdf-autotable, xlsx via spreadsheet-safety) are dynamically imported inside export handlers, never statically on page routes; keeps ordinary screens light.
- Client query keys for society-scoped search include the society id so cached results never show after a society switch.
- Member-only SECURITY DEFINER RPCs are never executable by anon; only asset_qr_lookup, get_applicable_plans, get_public_pricing_settings and smart_qr_public_* are public, so signed-out callers cannot reach governance/privacy actions.
- Offline support is one static, data-free /offline.html served by the existing push service worker for failed navigations only; never cache API or society data in the worker.
- Occupancy boundary (reviewed): `global_search` is SECURITY INVOKER (table RLS also applies) and every resident branch requires an active `flat_residents` row; Flat 360 + its AI summary are admin/block-admin/super-admin only; No-Dues creation needs active occupancy, and past requesters see only their own request/certificate snapshot, never live eligibility. Keep these when editing.
- Role helpers (has_role, is_super_admin[_internal], is_society_admin_for_internal) count only active user_roles rows; a deactivated role must never keep access.
- Formal books (manual journals, trial balance, I&E, balance sheet, FY close, Tally-ready export, GST/TDS) read and write only the canonical finance_journal_* ledger via fin_*/admin_*tax RPCs (finance-books.functions.ts); trigger finance_journal_entries_closed_period blocks every posting path into a closed April–March year, and tax lives in expense_tax_calculations as calculation/reporting only (never posted or "filed"), so there is one financial truth.
- Data import: opening balances and past payments import through dry-run-capable RPCs keyed by request_id (retry = idempotent replay); undoing a finance import marks rows rejected/reversed, never deletes. Past payments (`historical_payments`) are record-only history and never post to the ledger or change dues, because the confirmed opening balance is the cutover point and posting both would double count. Migration-job rollback removes only records whose created_at equals that job's commit timestamp and refuses when anything depends on them.
- Gate authority (public._gate_society) requires guards to hold a live guard_sessions row bound to the JWT session_id; admin revoke blocks self-restart until a one-time 10-minute QR token is redeemed. Patrol, safety alerts and hardware RPCs all authorize through it, so revocation stops every guard path at once.
- Gate hardware (ANPR/RFID/barrier) enters only via /api/public/gate/device-event with per-device hashed keys, strict payloads and per-device event-id replay protection; society comes from the device row, barriers use a pull model so browsers never hold hardware secrets. Biometric unlock is disabled (fails closed) until a server-verified provider exists.
- Parking lifecycle lives in parking_allocations (permanent + temporary, history never deleted) written only via admin_parking_* RPCs; parking_slots.flat_id/vehicle_id mirror the current permanent holder for older readers, expiry is checked server-side (parking_sweep + time filters), move-out/vehicle-removal triggers release authorisation, and violations/EV sessions never create bills or ledger rows.
- Parking violation photos live in parking_violation_evidence + private parking-evidence bucket, written only via uploadParkingEvidence (byte-sniffed images, 5 MB, server-built path) → parking_record_evidence; readable only by gate staff on shift and the committee, removal is a reasoned soft-remove, so evidence never reaches residents and never alters the violation.
- Staff work is scoped server-side: maintenance_tasks (committee-scheduled via admin_schedule_maintenance, staff progress via staff_update_maintenance, completion logs service only), assets limited to those linked to the staff member's own open requests/tasks, and staff.gate is a read-only "inside now" view — guard actions stay with the security role.
- Community & Communication: resident marketplace lives in community_listings (+ reports/append-only events) written only via market_* RPCs (owner/admin checks, server-resolved society, controlled in-app contact, private community bucket); emergency broadcasts are emergency_broadcasts + per-recipient rows via emergency_broadcast_send (admin, idempotent request id, audience resolved server-side, never ads, SMS/WhatsApp/email recorded as not configured); document expiry uses society_knowledge_sources.expires_on + deduped document_expiry_reminders (committee/staff only); ad reporting is aggregate-only ad_event_daily via record_ad_event (eligibility re-checked, 30-minute dedupe), read only by Super Admin via get_ad_report.
- Invoice AI stores files in the private invoice-ai bucket and suggestions in invoice_extractions (results written only by service-role invoice_ai_record_result); an expense is created only by invoice_ai_confirm calling create_finance_expense after human review, so AI never mutates finance directly.
- Helpdesk AI drafts (helpdesk-ai.functions.ts) read only the one request via committee RLS or the staff_my_tickets/staff_ticket_timeline RPCs plus caller-visible FAQs/rules; they never write or send, so drafting can't widen Helpdesk permissions.
- Multi-home: the selected home is profiles.active_flat_id, set only via switch_active_home (server-validated current occupancy) and read via current_home_flat_id()/_my_active_flat(); resident "my home" screens scope to it, so one identity can hold many homes without duplicate accounts.
- Amenity eligibility lives only in _amenity_eligibility (owner/tenant/household flags, active tenancy, dues); waitlist promotion is _promote_amenity_waitlist (oldest first, each candidate re-checked) recorded in append-only amenity_waitlist_events with one 'promoted' row per booking; occupancy changes re-check future bookings.
- Lease agreements are society_knowledge_sources rows with category 'lease' linked to a flat_residents row (forced committee audience, excluded from AI), opened by the tenant only via my_lease_document_path while that tenancy is current.
- Vendor ratings live in append-only vendor_ratings, one per real interaction (resolved ticket with vendor, or asset service visit), written only via vendor_rate_ticket / admin_rate_vendor_service / admin_moderate_vendor_rating; helpdesk reports come only from helpdesk_report / helpdesk_report_rows (server-resolved society, staff limited to own assigned tickets, audited exports), so there is no second reporting or rating system.
- External messaging (email/sms/whatsapp) goes only through message_deliveries (deduped via _enqueue_message) dispatched by src/lib/messaging.server.ts with env-only credentials; missing credentials mark "not_connected", never fake success, and in-app _notify_user stays primary. Last-active is one throttled row per user in user_last_active via touch_last_active.
- Pets live in flat_pets (home-scoped, soft-removed) written only via resident_add_pet / resident_remove_pet with audit; readable by the current home and its committee, never a person-level record.
- Utility meters: utility_meters + append-only utility_meter_readings, written only via admin_register_meter / admin_record_meter_reading (monotonic readings, replacement instead of edits, audited); no utility billing until rates are explicitly configured.
- Community events: community_events + community_event_rsvps written only via admin_create_event / admin_cancel_event / event_rsvp (server society, capacity, FIFO waitlist promotion with notification, audited); kept separate from official notices.
- Community groups: community_groups + community_group_members written only via admin_save_group / admin_group_action / group_membership (server society, open or approval joining, audited); discussions stay in the existing feed.
